MAYAK 仕様書

OCR モデルの学習

MAYAK に同梱している Tesseract には、EFT の名前向けに追加学習したモデルが2つあります。

モデル元のモデル学習に使った名前使うとき
efteng（tessdata_best）英語のアイテム名・略称・タスク名いつでも
eftjpnjpn（tessdata_best）日本語のアイテム名・略称・タスク名（9,463件）ゲームが日本語のとき（eftjpn+eft）

どちらも build/tessdata/ に置いて Git で管理しています。task tesseract:bundle で、Mayak.exe の横の tesseract/tessdata/ にコピーされます。

仕組み

名前を丸暗記させているのではなく、ゲームと同じ見た目で描いた名前の画像から、文字の形を学習させています。そのため、ゲームに新しいアイテムが増えても、基本的にはそのまま読めます。照合に使う名前の一覧はカタログから自動で更新されるので、モデルの学習し直しは、読み間違いが目立ってきたときで十分です。

学習用の画像は tools/ocrtrain が作ります。

  • 64 文字（バイト数ではなく文字数）までの名前を使います。長い日本語名も対象です。
  • カタログの名前を、ゲームのフォントで、ゲームと同じ配色（明るい地に暗い字、または暗い地に明るい字）で描きます。
  • 大きさ、位置、文字の間隔、ノイズを少しずつ変えます。
  • 読み取り時と同じ前処理（ocr.PrepareForTesseract）を通します。
  • 名前の5%は学習に使わず、評価用にとっておきます。

フォント

言語フォント理由
英語Benderゲームの英字のフォント
日本語Meiryo、Yu Gothic（Regular と Medium）ゲームは Noto Sans CJK を埋め込み、Meiryo を代わりに使う設定になっている。近い字形のもの
日本語の中の英字・数字Benderゲームは日本語名の中の英字も Bender で描く（-latin-fonts）

太さを変えられる可変フォント（NotoSansJP-VF など）は、生成ツールでは一番細い既定の太さで描かれてしまうので使いません。

学習の結果（eftjpn）

学習に使っていない名前での誤り率です。

モデル文字の誤り率単語の誤り率
元の jpn21.1%41.8%
英字も日本語フォントで学習6.8%17.2%
英字を Bender で描き分けて学習1.8%3.3%

その後、学習データ生成が名前の長さをバイト数で数えていて、約21文字を超える日本語名（392件）が学習から漏れていたことが分かりました。長い名前を加えた 9,463 件で、上のモデルから追加学習したものを採用しています。長い名前を含む評価用の名前での比較です。

モデル文字の誤り率単語の誤り率うち 22 文字以上の名前（文字）
追加学習の前1.6%3.1%0.27%
長い名前を加えて追加学習（採用）1.6%3.1%0.22%

実際の日本語のスクリーンショット13枚は、どちらのモデルでもすべて正しく照合できました。

手順

詳しい手順とコマンドは、tools/ocrtrain/README.md（英語）にあります。大まかな流れは次のとおりです。

  1. 元のモデル（tessdata_best）、フォント、カタログを用意する。
  2. go run ./tools/ocrtrain -lang ja ... で、学習用の画像と正解を作る。
  3. Tesseract で、画像を学習用ファイル（.lstmf）に変換する。
  4. lstmtraining で追加学習する（6,000〜8,000回程度。CPU で30分前後）。
  5. 評価用の名前と実際のスクリーンショット（cmd/ocrharvest）で、元のモデルより悪くなっていないことを確かめてから採用する。

作業用のファイル（フォント、学習データ、途中の保存）は build/ocrtrain-*/ に置きます。ここは Git の対象外です。

Tarkov OCR model (eft.traineddata)

MAYAK reads quest and item titles with the bundled Tesseract. The eft model is Tesseract’s English LSTM model fine-tuned on Escape from Tarkov titles in the game’s font; internal/ocr uses it instead of eng whenever the bundled tessdata directory contains it. The model lives in build/tessdata/eft.traineddata and task tesseract:bundle copies it next to Mayak.exe.

Retraining

Tools come from the UB Mannheim build that task tesseract:bundle unpacks into build/tesseract-cache/extracted (tesseract.exe, combine_tessdata.exe, lstmtraining.exe, lstmeval.exe). Paths below are examples.

  1. Inputs:

    • Bender font (SIL OFL), e.g. from 1001fonts.com, unpacked to fonts/.
    • eng.traineddata from tesseract-ocr/tessdata_best (only the “best” float models can be fine-tuned).
    • A MAYAK catalog snapshot: %AppData%\Mayak\catalog\pve.json.

  2. Generate line images, ground truth and box files. Every image goes through ocr.PrepareForTesseract, the preprocessing used when reading:

    go run ./tools/ocrtrain -catalog %AppData%\Mayak\catalog\pve.json -fonts fonts -out data

  3. Turn each line into an .lstmf file:

    tesseract data/lines/NAME.png data/lines/NAME --psm 13 lstm.train

  4. Extract the LSTM network and fine-tune it:

    combine_tessdata -e eng_best.traineddata eng.lstm
lstmtraining --continue_from eng.lstm --traineddata eng_best.traineddata \
  --model_output out/eft --train_listfile data/train.txt --eval_listfile data/eval.txt \
  --max_iterations 8000

  5. Write the integer (fast) model and compare it with the original:

    lstmtraining --stop_training --convert_to_int --continue_from out/eft_checkpoint \
  --traineddata eng_best.traineddata --model_output eft.traineddata
lstmeval --model eng.lstm --traineddata eng_best.traineddata --eval_listfile data/eval.txt
lstmeval --model out/eft_checkpoint --traineddata eng_best.traineddata --eval_listfile data/eval.txt
go run ./cmd/ocreval -dir "<Screenshots>/Mayak-Debug" -tesseract build/bin/tesseract/tesseract.exe \
  -tessdata <dir with eft.traineddata> -lang en

    Replace build/tessdata/eft.traineddata only when both the held-out lines and the real screenshots (cmd/ocreval) do not get worse.

Japanese model (eftjpn.traineddata)

internal/ocr reads Japanese titles with eftjpn instead of jpn when the bundled tessdata has it. It is jpn from tessdata_best fine-tuned the same way, on the catalog’s Japanese item and task names:

  1. Inputs:

    • Japanese fonts like the game’s (it embeds Noto Sans CJK and falls back to Meiryo): meiryo.ttc, YuGothR.ttc and YuGothM.ttc from C:\Windows\Fonts in fonts-ja/. Variable fonts (e.g. NotoSansJP-VF) draw at their thinnest weight here: leave them out.
    • Bender in fonts/: the game draws the Latin letters and digits in Japanese names with it.
    • jpn.traineddata from tessdata_best, saved as jpn_best.traineddata, and a tessdata directory with it as jpn.traineddata plus configs/ (for lstm.train).
    • A catalog snapshot with items_ja and tasks_ja (MAYAK fetches both).

  2. Generate the lines:

    go run ./tools/ocrtrain -lang ja -catalog %AppData%\Mayak\catalog\pve.json -fonts fonts-ja -latin-fonts fonts -out data-ja

  3. Make the .lstmf files with --tessdata-dir <that directory> -l jpn, then extract jpn.lstm from jpn_best.traineddata and run lstmtraining as above with --max_iterations 8000. Convert the best checkpoint with --convert_to_int to eftjpn.traineddata.

  4. Compare with lstmeval against jpn.lstm, and on real Japanese screenshots with go run ./cmd/ocrharvest -lang ja -tesseract <dir with tesseract.exe and tessdata incl. eftjpn>. Keep it only when neither gets worse.
