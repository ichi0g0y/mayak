# ブラウザシェル

MAYAK のメインウインドウは、自前のブラウザシェル（`frontend/src/browser`、vanilla JS）です。シェル自身はタブ一覧・ツールバー・設定・ブックマーク・アイテムサイドバーを描画し、Web ページはシェルとは別のネイティブ WebView（Windows では WebView2 の子ウインドウ）で表示します。

この章では、現在のコードの挙動と、それを実装しているファイルを説明します。アイテムサイドバーの中身は [item-panel.md](item-panel.md)、タスク・マップの自動表示は [tasks-and-maps.md](tasks-and-maps.md)、設定画面と Host 連携は [settings-and-integrations.md](settings-and-integrations.md) を参照してください。

## 構成ファイル

| `frontend/src/browser/shell-core.js` | シェルの各部が共有するもの: `window.mayak`、現在の状態 `state`、`action`、`render` の入口、`t` と HTML の部品（`esc`、`icon`、`select`）。ビューはここから import し、`shell.js` からは import しない |
| `frontend/src/browser/view-snapnotes.js` | スナップノート: ツールバーのボタンとメニュー、サイドバーの欄、一覧と書き込み画面（[スナップノート](#スナップノート)） |
| `frontend/src/browser/view-map.js`, `map-geo.js`, `map-draw.js`, `squad-draw.js`, `squad-share.js`, `view-squad.js` | マップ: Leaflet の地図、フィルターで出し分ける地点、仲間の印（[マップ](#マップ)）。`map-draw.js` は自分のペンと分隊ペン、`squad-draw.js` は分隊ペンの線の送受信、`squad-share.js` は分隊への共有、`view-squad.js` はサイドバーの分隊セクションと分隊ページ（[分隊](#分隊)）。`map-geo.js` は、地図と階の選び方、地点の種類と色、印の向きなど、Leaflet を使わない計算 |

| `frontend/src/browser/api.js` | 状態の保持と操作（`window.mayak.action`）、ネイティブビューへの命令、永続化、ナビゲーションイベントの受信 |
| `frontend/src/browser/state.js` | 既定値、`browser.json` の復元と検証、タブ・ブックマークの並べ替え規則、URL 検証 |
| `frontend/src/browser/tab-drag.js` | タブのドラッグによる並べ替え |
| `frontend/src/browser/popup.js`, `frontend/popup.html` | アイテムポップアップウインドウのヘッダー |
| `frontend/src/browser/style.css` | レイアウト（縦・横）、タブの縮小、ロードバーなど |
| `app_browser.go` | `browser.json` の読み書き、`BrowserView` 命令の検証 |
| `app_popup.go`, `app_popup_windows.go` | アイテムポップアップウインドウ |
| `app_favicon.go` | ファビコンのディスクキャッシュ |
| `app_adblock.go`, `internal/adblock` | 広告ブロック |
| `internal/browserview/*` | ネイティブビューの管理（Windows / macOS / Linux 実装） |

## ウインドウとレイアウト

### ウインドウ

- メインウインドウはシェルが上端まで描きます。Windows と Linux はフレームレス（`internal/app/run.go` の `Frameless`）で、シェルが右上に Windows 風の最小化・最大化・閉じるのボタンを描きます。macOS はタイトルバーを透明にして隠し（`MacTitleBarHidden`）、macOS 自身の赤・黄・緑のボタンを残します。ボタンは `internal/app/window_buttons_darwin.go` が 48px の行の縦中央（1 つ目の中心が左から 22px）へ動かし、サイズ変更・フルスクリーンからの復帰・アクティブの切り替えのたびに置き直します。macOS では左上にあるもの（縦レイアウトで左のサイドバーの上段、右サイドバーのときのツールバー、そのとき左に開いたアイテム欄のタイトル行、横レイアウトのタブ列）を `--lights`（90px、macOS 26 でボタンの左右に 15px ずつ）だけ右へずらし、左のサイドバーを畳んだときも、アイコンの列は他の OS と同じ 52px です。Finder や Safari のように、上の段はツールバー（アイテム欄も左に開いているときはそのタイトル行）がボタンの右から始まります（`body[data-frame=mac]`）。フルスクリーンでは macOS がボタンを隠すので、`--lights` を 0 にします（`data-fullscreen`）。Windows の影・角丸・スナップは維持されます。既定サイズ 1120×760、最小 760×560。
- 最小化・最大化・閉じるボタンはシェルが描画します（`windowControls()`）。`--wails-draggable: drag` の領域（縦レイアウトではサイドバー上部とツールバー、横レイアウトではタブストリップとドック。アイテムサイドバーの上部も）でウインドウを移動でき、ダブルクリックで最大化を切り替えます。
- タイトルバーと枠の色は、テーマの `--sidebar` / `--text` / `--border` と明暗から `BrowserSetWindowTheme` で設定します（`applyTheme()`）。OS のテーマが変わると Wails がボタン色を戻すため、300ms 後にもう一度送り直します。
- ウインドウ位置とサイズは `window.json` に保存され、起動時に画面内へ収めて復元されます（`main.go`）。
- トレイ: 設定 `MinimizeToTray` なら最小化時に、`CloseToTray` なら閉じるときにウインドウを隠します。トレイメニューは「MAYAKを開く」と「終了」で、設定の言語を変えるとすぐその言語に切り替わります。多重起動時は既存ウインドウを表示します。

### タブ欄とアイテム欄の位置

設定の「表示」で、タブ欄は左・右・上、アイテム欄は右・左・下から選べます（`navPosition` / `itemDock`）。両方を同じ側に置くと、外側がタブ欄、内側がアイテム欄になります。

- タブ欄の左・右は `layout: 'vertical'` と `sidebarSide`、上は `layout: 'horizontal'` で保存します。ドックの配置ボタン（アイコンは今のタブ欄の位置）を押すと、タブ欄とアイテム欄の位置をアイコンで選ぶメニューが開きます（`placeMenuHTML()`）。縦レイアウトではボタンの上、横レイアウトでは下に開き、ページ領域に重なるときはその間ページビューを隠します。選ぶとすぐ切り替わり、メニューは閉じます。Esc・外側のクリック・ウインドウのリサイズでも閉じます。
- シェルは `body` の `data-nav`（`left` / `right` / `top`）と `data-item`（`right` / `left` / `bottom` / `closed`）から、ページ領域の余白 `--page-left` / `--page-top` / `--page-right` / `--page-bottom` を CSS で計算します。`main`、スクショの拡大表示、Host 設定の iframe、設定の閉じるボタンはこの余白に従います。ネイティブビューは同じ値を `bounds()` で計算します（後述）。
- 右のタブ欄はツールバーの行の下から始まり、ウインドウ操作ボタンはツールバーの右端（ウインドウの右上）に残ります。
- 下のアイテム欄はページ領域と同じ幅で、ボタンを左に縦に並べ、中身を幅 280px ごとの段組みにして縦にスクロールします。高さは上端をドラッグして 180〜560px（既定 280px、`itemPanelHeights`）で変えられます。
- アイテム欄のスクロールバーは Mac のように、スクロールしているあいだかポインタが上で動いているあいだだけ出し、1.2 秒後に消します（`body[data-item-scroll]`）。

### 縦レイアウト（左右のサイドバー）

`layout: 'vertical'`（既定）。以下は左に置いた場合です。右に置くと左右が入れ替わります。

- 左サイドバーに、上から状態表示、「マップ」（[マップ](#マップ)）、分隊（[分隊](#分隊)）、スクリーンショット、スナップノート、ボス、ピン留めしたブックマーク（既定で tarkov.dev と TarkovTracker。タブのすぐ上）、タブ一覧が並びます。下部のドックにはサイドバー開閉・配置・アイテムサイドバー・設定のボタンがあります（開閉ボタンは上のウインドウのボタンから離して下に置きます）。
- ツールバー（高さ 48px）はサイドバーの右、ページはその下に置かれます。
- サイドバーの幅は右端をドラッグして 180〜420px の範囲で変えられます（既定 224px、`sidebarWidths`）。ダブルクリックで既定値に戻ります。ドラッグ中は CSS 幅がすぐに追従し、ページのネイティブビューは 1 フレームに 1 回追従し、幅はドラッグ終了時に保存されます。
- サイドバーを閉じると幅 52px のアイコンだけの表示になります（`sidebarCollapsed`）。タブ名・操作ボタン・状態表示は隠れます。
- ブックマーク欄は見出しクリックで折りたためます（`bookmarksCollapsed`）。

### 横レイアウト（上部タブストリップ）

`layout: 'horizontal'`。

- 1 段目（高さ 48px）: マップ、ピン留めブックマークのアイコン、タブ、新規タブボタン。右端に幅 180px のドック（状態表示を含む）とウインドウ操作ボタン。
- 2 段目: ツールバー。ページは上から 96px の位置から始まります。
- タブは Chrome のように縮みます。タブ列全体はタブ数 × 182px を上限に伸び（`--n`）、各タブは最大 180px・最小 40px です。コンテナ幅が 72px 以下になると、タブ名と操作ボタンを隠してアイコンだけにします（`style.css` の `@container (max-width:72px)`）。
- ピン留めタブとその他のタブの間には区切り線が入ります。
- サイドバーのリサイズと開閉は横レイアウトでは使えません。

## タブ

### 種類

| 種類 | 内容 |
| --- | --- |
| `web` | ネイティブビューで表示する Web ページ |
| `blank` | 新しいタブ（アドレス入力待ち） |
| `settings` | 設定ページ（1 つだけ） |
| `bookmarks` | ブックマーク一覧ページ（1 つだけ） |
| `screenshots`, `snapnotes`, `bosses`, `tabs` | スクリーンショット、スナップノート、ボス、タブ一覧のページ（それぞれ 1 つだけ） |
| `livemap` | マップ（1 つだけ。nightly 版と開発版のみ） |

- タブ一覧に並ぶのは `web` と `blank` のタブだけです（`listedTabs()`）。設定・ブックマーク・マップなどシェル自身のページは、ドックやサイドバーの項目から開きます。
- 設定を開いている間、サイドバーはタブの代わりに設定のセクション一覧を表示します。設定を閉じると、開く前のタブ（なければマップ、それもなければ設定以外の最初のタブ）に戻ります。
- タスク検出で開いたタブ（`role: 'task'`）には、ツールバーにサイト選択と Wiki 内検索が付きます（[tasks-and-maps.md](tasks-and-maps.md)）。
- タブは合計 80 個まで（`tab-limit`）。ネイティブビューも 80 個までです。

### tarkov.dev と TarkovTracker

以前はサイドバーの先頭に、閉じられない固定ビュー（TARKOV.DEV・TarkovTracker）がありました。今はどちらもサイドバーにピン留めした既定のブックマーク（`https://tarkov.dev/`、`https://tarkovtracker.org/`）で、開くと普通の `web` タブになります。マップの検出は tarkov.dev のタブではなく [マップ](#マップ) に入ります。

- 以前の `browser.json` は、`bookmarkRevision` 3 への移行で 2 つをブックマークに加えてサイドバーにピン留めします（同じ ID か URL のブックマークがあればそれをピン留め）。保存されていた固定ビューのタブ（ID `map`・`tracker`、`formerFixedTabIDs`）は捨てます。
- tarkov.dev のマップページ（`/map/…`）とマップ一覧（`/maps/`）は、どのタブで開いても Host のドキュメントスクリプトが `?connection=<Remote Control ID>` を付けて Remote Control につなぎます（[tasks-and-maps.md](tasks-and-maps.md#remote-controltarkovdev)）。保存されるタブの URL からは取り除きます（`pageURL()`）。

### ピン留め・並べ替え・閉じる

- ピン留めできるのは `web` タブだけです。並び順は常に「ピン留め → その他」（`orderTabs()`）。ピン留めするとピン留めグループの末尾へ、外すとその他のグループの先頭へ移ります。
- ピン留めタブには閉じるボタンがなく、閉じられません。
- ドラッグでの並べ替え（`tab-drag.js`）:
  - 5px 以上動かすと開始します。つかんだタブがポインタに追従し、ほかのタブが移動先を空けます。
  - 並べ替えはピン留めグループ内、その他グループ内でのみ行えます。
  - Esc でキャンセル。ドラッグ後のクリックは無視されるため、タブの切り替えや閉じる操作にはなりません。
  - サイドバーのブックマーク欄（またはブックマークアイコン）の上で離すと、`web` タブをブックマークしてサイドバーにピン留めします（同じ URL のブックマークがあればそれをピン留めします）。
  - ページのネイティブビューの上やアプリの外で離した場合、シェルにはイベントが届きません。そのため、フォーカスが外れたとき、ボタンが離された状態で pointermove が来たとき、pointer capture を失ったときにドラッグを破棄します。
- タブを閉じるとネイティブビューも破棄され（読み込み中の状態 `loadingViews` からも外します）、右隣（なければ左隣）のタブがアクティブになります。

### 起動をまたいだ状態の保存（`browser.json`）

`api.js` の `persist()` が `%AppData%\Mayak\browser.json`（`os.UserConfigDir()` 配下）に保存します。書き込みは 1 MiB 以下の有効な JSON のみ受け付け、一時ファイルに書いてから置き換えます（`BrowserSave`）。

| キー | 内容 / 既定値 |
| --- | --- |
| `version`, `bookmarkRevision` | 形式のバージョン。`bookmarkRevision` は現在 3（2 で TarkovTracker を `.org` へ移行、3 で tarkov.dev と TarkovTracker をサイドバーにピン留めしたブックマークに） |
| `language` | `ja`（既定）/ `en` |
| `clock` | 時刻の表示。`24`（既定）/ `12`。Host 設定の画面（iframe）にも `data-clock` で伝えます |
| `layout` | `vertical`（既定）/ `horizontal` |
| `sidebarSide` | 縦レイアウトのタブ欄の側。`left`（既定）/ `right` |
| `itemDock` | アイテム欄の位置。`right`（既定）/ `left` / `bottom` |
| `sidebarCollapsed`, `bookmarksCollapsed`, `screenshotsCollapsed` | `false` |
| `bossesView` | ボス欄の開閉。`full`（既定・マップのボスも表示）/ `goons`（Goons だけ）/ `closed` |
| `bossMap`, `bossMode` | ボス欄で手で選んだマップ（正規化名）とモード（`regular` / `pve`）。空は自動 |
| `sidebarWidth` | 224（180〜420） |
| `itemPanelWidth` | 320（260〜560） |
| `itemPanelHeight` | 下に置いたアイテム欄の高さ。280（180〜560） |
| `itemPanel` | `{open, id, mode}`。アイテムサイドバーの開閉と表示中のアイテム |
| `bookmarkView` | `grid`（既定）/ `list` |
| `favicons` | ホスト名 → ファビコン URL（最大 200 件） |
| `theme` | `mayak-dark`（既定）。`system` と 12 種のテーマ |
| `adblock` | `true` |
| `taskMode` | `new`（既定）/ `reuse` |
| `questSite` | 以前のサイト選択（`host` が既定）。Host で起動したときに Host の順番の先頭へ移す。タスクを開くサイトは Host の `questSites` で決まる |
| `bookmarks` | 最大 100 件 |
| `tabs`, `active` | タブ一覧とアクティブなタブ |
| `mapHidden`, `mapSettings`, `mapCollapsed`, `squadName`, `squadColor`, `squadCollapsed`, `squadCode`, `squadRecent` | マップの隠した層・設定・畳んだまとまり、分隊の表示名・分隊カラー・サイドバーのセクションを畳んだか・参加中のコード・最近の分隊（[マップ](#マップ)、[user-data.md](user-data.md)） |
| `connection` | `{mode, link, receive}`。接続モード（`local` / `client`。前の版の `off` は `client` にする）、ペアリングの鍵と役割（`link: {key, role}`、なければ `null`）、Client で出すもの（`receive: {task, map, item}`）。接続コードは保存しません（[settings-and-integrations.md](settings-and-integrations.md#host--client-モード)） |

ウインドウの位置とサイズは `browser.json` には保存しません（`window.json`）。以前のファイルにある `window` は読み込まず、次の保存で消えます。

復元時（`restore()`）の検証:

- タブ ID は `^[a-zA-Z0-9_-]{1,80}$`。重複と、以前の固定ビューの ID（`map`・`tracker`）を持つ保存タブは捨てます。
- `web` タブは有効な http/https URL のものだけ残します。`settings`・`bookmarks`・`livemap` などシェル自身のページは 1 つずつ。
- 保存タブは 79 件まで。
- タイトルは 160 文字、ブックマーク名は 150 文字、分類名は 40 文字で切り詰めます。
- 初回起動の既定タブはマップ（`livemap`）と設定で、アクティブはマップです（`defaults()` の `active`）。マップの無いリリース版では、マップのタブを外します（`SquadAvailable`）。
- 設定のタブは、アクティブなタブとしては復元しません（起動は設定ではなく、保存されていた別のタブか先頭のタブから）。

## ブックマーク

- 各ブックマークは `id`, `name`, `url`, `group`, `sidebar`（サイドバーにピン留め）を持ちます。
- 分類（`group`）は組み込みの `maps` / `tasks` / `items` / `progress` / `other`（表示時に翻訳）と、ユーザーが入力した任意の名前です。空欄なら `other`。
- 既定のブックマークは tarkov.dev（Maps / Items）、日本語 Wiki・公式 Wiki のタスクページ、TarkovTracker、Tarkov Market、Database for Tarkov、EFT Ammo です。
- ブックマークページでは検索（名前・URL）、タイル / リスト表示の切り替え、追加・編集・削除、サイドバーへのピン留めができます。
- サイドバーへのピン留めは、ブックマークページからブックマーク欄へドラッグするか、ピンボタンで行います。ドロップ位置に挿入され、ブックマーク欄の中でドラッグすると並べ替えになります。
- ピン留めブックマークを右クリックすると「開く」「サイドバーから外す」のメニューが出ます（矢印キー・Esc 対応）。
- ブックマークを開くと新しいタブで開きます。

## スクリーンショット

ゲームのスクリーンショット（Host の設定のスクリーンショットフォルダ）を見られます。Host の PC（接続モード `local`）でだけ表示します。

- **サイドバー:** ブックマークの下に「スクリーンショット」の欄があり、最新の1枚の縮小画像と撮影からの時間を出します。新しいスクリーンショットが撮られると（`browser:screenshot` イベント）、自動で入れ替わります。
  - 縮小画像をクリックすると、スクリーンショットのページでその1枚を大きく表示します。
  - 見出しの右のカメラのアイコンをクリックすると、スクリーンショットのページで一覧を表示します。
  - 見出しをクリックすると、ブックマークと同じようにプレビューを畳めます（`browser.json` の `screenshotsCollapsed`）。
  - サイドバーを畳んだ状態と横バーのレイアウトでは、画像アイコンだけを出します。
- **スクリーンショットのページ:** ブックマークの一覧と同じく、タブ一覧には出ない専用のタブ（`kind: "screenshots"`）です。上部のツールバーにはアドレス欄を出しません。
  - 新しい順に最大 300 枚を一覧にし、縮小画像は 1 枚ずつ順に読み込みます（先頭 120 枚）。「フォルダを開く」でフォルダを開けます。
  - 1枚をクリックすると、ページ部分（サイドバーとアイテム欄の間）に大きく表示します。←→ キーやボタンで前後の1枚へ、Esc や × で一覧に戻ります。
- **大きく表示したときのズーム:** 全体が収まる大きさを 100% として、最大 800% まで拡大できます。別の1枚に移ると 100% に戻ります。
  - マウスホイールで、カーソルの位置を中心に拡大・縮小します。
  - 拡大中はドラッグで表示位置を動かせます。
  - ダブルクリックで、全体表示と等倍（画面の画素そのまま）を切り替えます。
  - 上部のボタン（縮小・拡大・全体表示）と、`+` / `-` / `0` キーでも操作できます。
- **画像の受け渡し:** Go 側（`app_screenshot_gallery.go`）が JPEG の data URL にして渡します。縮小画像は横 480 px で、最大 400 枚をメモリに保持し、ディスク（`Mayak\thumbs\<名前・更新時刻・サイズの SHA-256 先頭 8 バイト>.jpg`）にも置きます。次の起動からはファイルを読むだけなので、起動のたびに数百枚の 1440p PNG をデコードしなくなります（それが起動直後の CPU の山で、Process Lasso などに優先度を下げられる原因でした）。書き込みは一時ファイルから改名、50 件書くごとに古い順に最大 1,500 件へ間引きます（ゲーム側で消したスクリーンショットの分が残るため）。受け付けるのはスクリーンショットフォルダの直下にある `.png` / `.jpg` / `.jpeg` だけで、パスを含む名前は拒否します。

### 判定の記録

Host がスクリーンショットを解析するたびに、何と判定したか（種類・画面の形・検出スコア・マップ・レイド中か・一致したタスクやアイテムと一致度・上位3件の候補・OCR の読み取り結果（400文字まで）・座標・エラー）を、ファイル名ごとに `%AppData%\Mayak\screenshots.json` に記録します（`screenshotstore.Index`、最大3000件で古いものから消えます）。画像はコピーしません。記録すると `browser:screenshot` を送り、一覧が更新されます。

- この記録より前の解析は、スクリーンショットフォルダの `Mayak-Debug`（認識デバッグの保存）に JSON があれば、フォルダごとに1回だけ取り込みます（`DebugRecords`）。
- 一覧とサイドバーの縮小画像は、左上に種類（タスク・アイテム・出品・位置・判定なし）、左下に一致した名前を重ねて表示します。
- 大きく表示したときは、見出しに種類・一致した名前・一致度を出し、ⓘ ボタンで判定の詳細（候補・画面の形・スコア・OCR など）のパネルを開閉します。

## スナップノート

表示中のページを撮影して、その上に書き込むメモです（`view-snapnotes.js`、`internal/app/app_snapnote.go`、`internal/snapnote`）。今は Windows だけです。

- **撮影**: Web ページのツールバーの付箋のボタン（スナップノートのアイコン。ペンの鉛筆やスクリーンショットのカメラと見分けるため付箋）でメニューを開き、「見えている範囲を撮る」か「ページ全体を撮る」を選びます。メニューはページを隠さず、その上に別ウインドウで開きます（[ページの上のメニュー](#ページの上のメニュー)）。翻訳表示のページでは、撮る直前に Google 翻訳のバー（`gt-` で始まる ID の要素と翻訳のフレーム）と、そのためにページ上端に空けてある余白を隠し、撮った直後に戻します（`app_snapnote_translate.go`。DevTools の `Runtime.evaluate`）。撮影は WebView2 の DevTools 呼び出し（`Page.captureScreenshot`。全体は `Page.getLayoutMetrics` の大きさで `captureBeyondViewport`）で、高さは 15000 CSS px で切ります（`browserview.MaxCaptureHeight`）。画像は画面の画素で返るので、表示倍率が高いときは縦 20000・横 8192 画素に収まるよう縮小して撮ります（`captureClip`）。ページの中の枠だけがスクロールするサイト（マップなど）は、全体でも見えている範囲と同じになります。
- **ページとの紐付け**: 撮ったノートは URL・タイトルを覚えて紐付きます。同じページかは、翻訳表示の元の URL で、`#` 以降と末尾の `/` を除いて比べます（`snapPageKey`）。紐付いたノートがあるページではボタンに件数が付き、メニューからそのページのノートを開けます。ノートからは「元のページを開く」で戻れます。「ページとの紐付けを外す」と単独のノートになりますが、URL は残り、あとで付け直せます。
- **スクリーンショットから**: スクリーンショットのビューアーの「スナップノートにする」で、そのスクショから単独のノートを作り、すぐ書き込み画面で開きます（`SnapNoteFromScreenshot`。Screenshots フォルダ直下の画像ファイルだけ。タイトルは「スクリーンショット」と撮った日時）。
- **単独のノート**: 一覧ページの「白紙から作る」（1600×1000 の白）、「画像ファイルから作る」、または一覧ページでの Ctrl+V（クリップボードの画像）で作ります。画像はシェルで PNG にしてから渡します。
- **見るのと書き込むの**: ノートは、開くとまず見るだけ（プレビュー）です。道具の列は「編集」とズームだけで、レイヤー欄は出さず、タイトルは書き換えられず、描けません（数字キーや Ctrl+Z も効かない）。「編集」で書き込み画面になり、道具の列の先頭の「完了」で見るだけに戻ります（ノートごとに開くたび見るだけから）。作ったばかりのノート（撮った・白紙・画像から。作ってから 15 秒以内に開いたもの）は描くために作るので、最初から書き込み画面です。分隊の仲間から届いたノートは見るだけで開きます。個人のノートも共有のノートも同じです。
- **送った人**: 分隊の仲間から届いたスナップノート（分隊の欄・分隊ページから開いて取り込んだもの）は、送った人の名前と分隊カラーを覚えます（`SnapNoteSetFrom`、ノートの `from`）。一覧のカードと、開いたノートの上の行に「(名前) から」と出します。
- **書き込み**: 書き込み画面はページ表示の領域いっぱいに広がります。戻る・タイトル・保存の状態・元のページを開く・紐付け・削除は、Web ページならアドレス欄がある上端のツールバー行に置きます（`snapToolbar`。空の行が余白に見えないように）。ペン（6 色・3 段階の太さ）と、触れた線ごと消す消しゴム、元に戻す／やり直す（Ctrl+Z／Ctrl+Y、100 回まで）、線をすべて消す。ズームは既定が幅に合わせる表示で、Ctrl+ホイール（ポインタの位置を中心に）、Ctrl++／Ctrl+-、Ctrl+0（幅に合わせる）と、ツールバーの −／倍率（押すと 100%）／＋／幅に合わせる で変えられます（10%〜800%）。元の画像は編集せず、その上に書き込み用のレイヤーが 3 枚あります（右のレイヤー欄。上からレイヤー 3・2・1、いちばん下が元の画像）。描くレイヤーを選び（数字キー 1〜3 でも）、ペンと消しゴムは選んだレイヤーにだけ効きます。元の画像と各レイヤーは目のボタンで表示・非表示を切り替えられ、非表示のレイヤーに描き始めると表示に戻ります。元の画像を隠すと市松模様の上に線だけが見え、一覧用の縮小画像も表示中のものだけで作ります。レイヤーごとに線を消せます（ツールバーのごみ箱は選んだレイヤー）。レイヤー欄の下の「見やすさの調整」で、元の画像の見え方だけを変えられます（明るさ 50〜300%、コントラスト 50〜200%、暗部を明るく 0〜100%）。明るさとコントラストは CSS のフィルター、暗部を明るくは SVG フィルターのガンマ補正（指数 1 から 0.3 まで）で、暗い部分だけを持ち上げて明るい部分は飛ばしません。EFT の暗いスクショで敵がいるかを見るときのためのもので、保存してある画像は変えません。調整値はノートごとに保存し、一覧用の縮小画像も同じ見え方で作ります。保存する形は `{v: 2, base: {visible, brightness, contrast, shadows}, layers: [{visible, strokes}] ×3}` で、線は画像の画素の座標で `{c: 色, w: 太さ, p: [[x, y], …]}`、太さは画像の幅に比例させます。レイヤーの前に描いたノート（線の配列）はレイヤー 1 に入ります。インクの canvas は約 2400 万画素までで、それより大きい画像は縮小した canvas に描きます。
- **保存**: 最後の変更の約 0.9 秒後に、タイトル・線・一覧用の縮小画像（幅 360px の JPEG。縦長の画像は上端）を保存します。一覧に戻るときと別のノートを開くときにも、未保存なら保存します。保存先は `%AppData%\Mayak\snapnotes\<ID>\`（`note.json`、`base.png`、`thumb.jpg`）で、再起動しても残ります。変更は `snapnote:changed` イベントでシェルに伝わります。
- **一覧**: サイドバーの「スナップノート」欄（最新のノート。折りたたみは `snapNotesCollapsed`）と、一覧ページ（タブ種別 `snapnotes`。「すべて／ページのノート／単独のノート」で絞り込み）。削除は 2 回押しで確定します。
- **再描画との関係**: シェルは状態が変わるたびに描き直すため、ノートの画像と canvas には `data-keep` を付け、morphdom はその印が同じ間は触りません。画像の読み込みと線の描画は、描画後のフック（`afterRenderHooks`）で行い、線が変わったときだけ描き直します（描いている途中の線を消さないため）。

## マップ

MAYAK が自分で描く tarkov.dev の地図です。tarkov.dev のマップと同じ地点をフィルターで出し分け、分隊コードを共有した仲間の位置も同じ地図に出します（`view-map.js`、`map-geo.js`、`internal/app/app_squad.go`、`internal/squad`、`internal/mapdata`）。v0.1.19 からはリリース版にも入っています（それまでは nightly 版と開発版だけで、`SquadAvailable` は今は常に true を返します）。

- **入口**: サイドバーのいちばん上（状態表示の下）にある「マップ」の行です。タブと同じ形で、行全体が押せ、表示中は選択中の色になり、右端に地図のアイコンがあります。マップの検出（`browser:map`、`browser:position`）でもこのビューが開くか前面に出て（`receiveMap` / `receivePosition`）、手で選んだマップと階は「自動」に戻ります（`mayak:map-follow`）。
- **画面**: ページ全体が地図です。ツールバーの行は空なので、地図はその下まで広がります（`body[data-page=livemap]`）。左上にズームのボタン、その下にアイコンの縦の列があり（分隊に入っているときは、その下にもう 1 つ、自分の分隊カラーの枠と分隊のアイコンの見出しを付けた「分隊の列」があり、分隊ペン・ピン・分隊の自動表示が入ります）、押すとその内容のパネルが列の横に開きます（もう一度押すか、×・Esc・地図を押すと閉じる）。右上にはレイドの時計 2 つ（tarkov.dev と同じく、モスクワ時間から実時間の 7 倍で進み、2 つは 12 時間ずれる。Factory は固定、The Lab は出さない）、レイドの長さと人数、地図の作者の帰属表示、右下にはポインタの位置のゲーム座標を出します。
- **アイコンの列**:
  - **マップ**: ゲームモード（自動・PvP・PvE・Season。地点のデータのモードで、ボスの出現率などが変わる。自動はプレイ中のモード）、マップの一覧（「自動」と各マップ）、階（「自動」・地上・各階）、表示の形（SVG とタイルの両方がある地図だけ。Abstract / Satellite）。今の階が、その地図を開いたときの階と違うときは、ボタンの横に階の名前を出します。
  - **フィルター**: tarkov.dev のマーカーの層を、tarkov.dev と同じまとまり（脱出・危険・目印・床置きの物資・コンテナ・スポーン・タスク・設備。`markerGroups` / `mapdata.Groups`）に分けたチェックボックスです。まとまりごとに一括で切り替えられ、畳めます。地名（maps.json の `labels`）も目印の中の 1 つの層です。既定ではすべての層を出します。アイコンは tarkov.dev のもの（MIT、`frontend/public/map-icons`）です。
  - **検索**: tarkov.dev と同じく、カンマで区切った語のどれかを名前・アイテム名・タスク名に含む地点だけを出します（`searchTerms` / `found`）。検索中は地名を出しません。
  - **スナップノート**: 見えている地図（ボタン類と自分のペンの線を除く）を modern-screenshot で画像にし、スナップノートにして書き込み画面で開きます。表示中の階の分隊ペンの線と自分のペンの線（上）は、まとめてノートのレイヤー 1 に線として入り、レイヤー 2・3 は書き足す用に空けます（画像のピクセルに直して `SnapNoteSave`。ノートで消したり隠したりできる）。tarkov.dev のタイルは CORS を返さずページから読めないので、Go の `BrowserMapTile`（`assets.tarkov.dev/maps/…` のタイルだけ）を通して取ります。スナップノートと同じく Windows だけです。
  - **自分のペン**・**分隊ペン**: 後述の [自分のペン](#自分のペン)、[分隊ペン](#分隊ペン)。
  - **設定**: 「狙撃 Scav のスポーンを常に表示」（既定オン）、「脱出地点を常に表示」、「進行中のタスクの印だけ表示」（TarkovTracker で完了・失敗したタスクの地点を隠す）、「地名を目立たなくする」のチェックと、「別の階の濃さ」（0〜60%、既定 20）、「脱出地点の名前の大きさ」「地名の大きさ」（50〜200%）のスライダーです。
- **地図**: Leaflet（`leaflet`）で描きます。Leaflet はビューを初めて表示したときに読み込む別 chunk です。地図の一覧と形は tarkov.dev の maps.json（`BrowserSquadMaps`。ETag 付きで 1 日ごとに確かめる）で、座標変換は tarkov.dev の `getCRS` と同じく、`coordinateRotation` で回してから `transform` で拡大・移動します。絵は SVG（tarkov.dev の Abstract）かタイル（Satellite）で、両方ある地図は設定 `style` で選び、タイルしかない地図（The Lab・Labyrinth・Icebreaker）はタイルで描きます。SVG は Go が階の表示を書き込んだ data URL（`BrowserSquadMapImage`）を `L.imageOverlay`（`<img>`）で貼るので、SVG の中身はシェルで動きません。地図は `#live-map`（`data-keep`）に描き、描画のあとに `afterRenderHooks` で状態に合わせます。
- **マップの自動**: 自分がレイド中なら自分のマップ、そうでなければ最後に位置を送った仲間のマップ、それもなければ Host の現在のマップです。
- **階**: 「自動」では、自分がそのマップにいれば自分の高さと位置から `floorFor`（`mapdata.Floor` と同じ規則）で選び、そうでなければ tarkov.dev が `show` を付けた階（Icebreaker の甲板）、それもなければ地上です。階の一覧から選ぶか、地図の上の Ctrl+ホイールで高さの順に 1 階ずつ動かせます（`floorOrder`。いちばん上と下で止まる）。別の階にある地点を押すと、その階に移ります。
  - 階を出しているとき、別の階のもの（地上の絵とタイル、別の階の地点、別の階の地名）は設定 `fade` の濃さで薄く出します。高さの無い地名は地上のものとして扱います（`Label.Ground`）。`show` の階では地上を薄くしません。
  - SVG の階は、SVG のその階のグループを薄くした地上の上に描きます。SVG に無くタイルだけの階は、そのタイルを地上の絵の上に重ねます。Satellite では、SVG にしか無い階は何も重ねません（地点で分かる。tarkov.dev の Satellite と同じ）。
- **地点**: tarkov.dev のカタログ（選んだゲームモード、自動ならプレイ中のモード）から `BrowserMapMarkers(name, language, mode)`（`mapdata.Markers`）が tarkov.dev の地図と同じ作り方で作り、Go がマップ・言語・モードごとに 10 分間覚えます。アイテムとタスクの名前は表示言語です。脱出は色付きの名前で、それ以外はアイコンで描き、押すと詳細のポップアップ（タスク、ボスと出現率、鍵の種類と電源、スイッチが動かすもの、必要なアイテム、物資の中身など）を開きます。脱出や危険地帯の範囲は、ポインタを乗せると多角形で出し、押すと出たままになります。タスクの地点のポップアップからは、認識したタスクと同じ規則（タスクのサイトとタブの開き方の設定）でタスクのページを開けます（`mapTask`）。
- **分隊の自動表示**: 分隊の列のボタン（`mapSquadFit`。`mapSettings.squadFit`、この PC のマップの設定。既定はオン）がオンなら、誰かの位置が新しくなったとき（その人の位置の時刻が前に見たものと違う）、その人が自分の出撃マップ（Host はレイド中のマップ、ほかは自分の最後の位置のマップ）にいて、そのマップを表示中なら、そのマップにいる分隊全員（自分も）が入るように地図を合わせます（`fitBounds`。余白 90 px、寄りすぎない上限あり）。そのマップに 1 人しかいないとき（ひとりで遊んでいるとき）は動かしません。オンにした瞬間にも 1 度合わせます。ペンを持っているときとピンを刺しているときは動かしません。別のマップを見ているときも動かしません。
- **分隊**: マップのボタンの列に分隊のボタンとパネルはありません（仲間の一覧と接続の状態はサイドバーの分隊セクション、作成・参加・表示名・分隊カラー・退出は [分隊](#分隊) のページ）。地図に出すのは仲間の印だけです。矢印（自分と仲間）の形は、マップの設定（歯車のパネル）の「矢印の形」で選べます（矢じり・tarkov.dev の矢印（丸に白い縁と白い矢印）・丸と向き。`mapSettings.markerShape`。色の付いていない部分をその人の分隊カラーで塗り、向いている方へ回す）。「矢印のエフェクト」で選んだエフェクト（なし・縁取り・光彩・パルス・ビーコン）を付けます（`mapSettings.markerEffect`）。色は選んだ色（`markerColor`）か、既定ではそれぞれの分隊カラーです。自分の矢印は白い縁のままなので見分けられます。この PC のマップの設定（ブラウザの好み）で、tarkov.dev のページには何も入れません。
- **伏せ字**: 分隊ページの分隊コード、参加の入力欄、最近の分隊のコードは、配信やスクリーンショットで漏れないよう「•」で出し、横の目のボタン（`shell-core.js` の `revealButton`、`data-action="reveal"`）で表示します。入力欄は `.masked`（`-webkit-text-security: disc`）で伏せます。表示したものは、もう一度押すかアプリを再起動するまで表示のままです（保存しません）。接続コードと Remote ID も同じです（[settings-and-integrations.md](settings-and-integrations.md)）。
- **保存**: 表示名 `squadName`、分隊カラー `squadColor`、分隊セクションを畳んだか `squadCollapsed`、隠した層 `mapHidden`、設定 `mapSettings`、畳んだまとまり `mapCollapsed` はブラウザの好み（`browser-preferences.json`）、分隊コード `squadCode` と最近の分隊 `squadRecent` はこの PC（`browser.json`）です（[user-data.md](user-data.md)）。起動時に、保存されたコードの分隊へ入り直します。「分隊を抜ける」でコードを消します。
- **共有する内容**: 表示名と分隊カラー、レイド中に位置のスクリーンショットを撮ったときのマップ・座標・向き・撮った時刻だけです（[settings-and-integrations.md](settings-and-integrations.md#分隊ルーム)）。新しいレイドが始まると前のレイドの位置を外し（最初の位置のスクリーンショットまで位置なし）、レイドが終わると「レイド外」を送ります（`squadDropPosition`。表示名・分隊カラー・メンバー鍵はそのまま）。位置を送るのは Host（`local`）だけです。Host では、分隊に入っていなくても自分の最後の位置を地図に出します。この最後の位置（`status.position`）も、レイドの開始と終了、マップが変わったときに消します（`app_logdetect.go`。新しいレイドの最初の位置のスクリーンショットまで矢印なし）。状態は位置がないとき `position` を省くので、`api.js` の `hostStatus` は `position` のない状態を「位置なし」と読みます。
- **印**: 仲間ごとに、名前から決まる色、名前、向きの矢印を出します。自分の印は白い縁取りです。矢印は薄くせず、時間では消しません（古い位置でも別の階でも同じ濃さで出し続ける。古さはサイドバーの何分前かで分かる）。新しいレイドに入るか、レイドを出ると、その人の位置は本人の報告で消えます。表示中は 30 秒ごとに描き直します。
- **帰属表示**: 右上に「By: 作者」（maps.json の `author`、無ければ Shebuka。押すと作者のページ）と「CC BY-NC-SA 4.0 · tarkov.dev」を出します。地図の絵には非営利・チート目的禁止の条件があるので、有料の機能の中では使いません。

### 分隊

分隊コードで集まった仲間（[分隊ルーム](settings-and-integrations.md#分隊ルーム)、`app_squad.go`、`internal/squad`）の、サイドバーのセクションとページです（`view-squad.js`）。マップと同じく nightly 版と開発版だけで、リリース版ではセクションを出さず、保存されたタブ（種類 `squad`）も外します。

- **サイドバーのセクション**: 「マップ」の行のすぐ下です。見出しの「分隊」の横に人数（見るだけの PC を除く）を、接続の色（接続済みは緑、届かないときと満員のときは黄）で出し、見出しを押すと畳めます（`squadCollapsed`、ブラウザの好み）。右端のボタンで分隊ページを開きます。分隊に入っているあいだは、その左に切断のボタン（`squadLeaveQuick`）があり、1 回押すと赤く「もう一度押すと切断」になって、4 秒以内にもう一度押すと分隊を抜けます（分隊ページの「分隊を抜ける」と同じ）。畳んだサイドバーと横並びの配置では出しません。
  - 分隊に入っているときは仲間の名前が分隊カラーの点付きで 1 人 2 段で並びます（見るだけの PC を除く。Client では自分の代わりに Host を「(あなた)」として出す）。
    - 1 段目の名前を押すと、その人のカードを開きます。Windows ではページの上に浮かぶメニューの窓（`menuShow`、行の種類 `card`）で名前の横に出し（Web ページのタブの上にも出る）、Mac などではサイドバーの中、名前のすぐ下に出します（もう一度押すと閉じる）。カードには、キャラクターの画像（その人がキャラクター画面「全般」のスクリーンショットを撮り、分隊に見せる設定なら。中継の分隊の枠 `picture` から `SquadPictures` で読む。自分のはこの PC の `profile.jpg`）、ゲーム内の名前、レベル・レイド・キル・生還率・K/D・プレイ時間（報告の `profile`）、TarkovTracker と同期していれば完了したタスクの数とモード（報告の `tracker`）を出し、「マップで表示」「TarkovTracker で見る」（`tarkovtracker.org/profile/<ユーザー ID>/<モード>`。本人がそのモードのプロフィールの共有をオンにしていると見られる）「この人が共有したものを見る」を選べます。情報が何も無ければ、全般のスクリーンショットで出ることを書きます。
    - 位置の行を押すと、マップでその人を表示します（`squadFocus`。マップを前に出して、その人のマップと階に切り替え、今の拡大率のままその人を真ん中にし、その人の矢印から分隊カラーの波紋を 4 回出す。拡大はしない）。
    - 1 段目の右には、その人から来てまだ見ていないもの（ページ・スナップノート・ピン）があれば点が出ます（数は出さない）。
    - 名前の下には、いつも開いた小さなツリーで、その人の最新の「位置」（マップと何分前か。押すと上と同じくマップでその人を表示。位置が無ければレイド外などを押せない行で）・ページ・スナップノート・ピンを、この順に 1 件ずつ出します（無いものは出さない。種類のアイコン、タイトル、何分前か。未読なら太字）。押すとそれを開き、開いたあとも最新として残ります。同じ種類がほかにもあれば、行の右に「+N」を出し、押すと分隊ページを「その人 × その種類」に絞って開きます。描いたことはツリーに出さず、「マップ」の横の点で知らせます。
    - 共有したものを名前の下にツリーで開くことはしません（全部は分隊ページで見る）。
  - 入っていないときは「分隊を作る・参加する」のボタンだけです（分隊ページを開く）。
  - 畳んだサイドバーと横のタブ欄では、ほかのセクションと同じくボタンだけになります。
- **分隊ページ**（種類 `squad`、`squadPage`）: 上に「あなたのプロフィール」（表示名と分隊カラー。分隊に入っていてもいなくても同じもの）、下に分隊のカードです。
  - 表示名の既定は TarkovTracker の表示名です（ゲームのログには自分の名前が出ないため、自分で付けます）。Enter か欄を離れたときに変わります。
  - 分隊コードは 1 文字ずつ 8 つの枠（4 文字ずつ、ハイフンは打たない）に打ちます。接続コードと同じ部品（`code-boxes.js`）で、打つと次の枠へ進み、貼り付けで埋まり、8 文字目でそのまま参加します。
  - 入っていないとき（「分隊に入る」）: 説明、「分隊を作る」（`SquadNewCode` で新しいコードを作って参加）、仲間から聞いたコードの「参加」（`SquadJoin`）、最近の分隊、共有する内容です。コードは Crockford base32 の 8 文字（`ABCD-1234`。小文字・空白・O/I/L も受け付けます）です。表示名は 24 文字まで、分隊は 10 人までです。作ったり入ったりしても、ページはそのままです（共有するコードが見える）。
  - 入っているとき（「参加中の分隊」）: コード（伏せ字、コピー）、接続の状態（「接続しています…」「接続済み」、届かないときと満員のときはその旨）、メンバーの一覧、「分隊を抜ける」、共有する内容です。
  - 「最近の分隊」（最大 5 件、30 日使わなければ消える。`squadRecent`）は押すだけで入り直せます。コードは伏せ字で、見出しの目のボタンで表示します。中継は分隊を何も残さず、誰もいなくなった部屋は消えますが、同じコードでまた集まれます。
- **分隊カラー**: 地図の印・一覧の点に使う、分隊の中での自分の色です。「自動」か、10 色の候補（`map-geo.js` の `squadColors`）か、最後の丸（システムの色の選択。閉じたときに決まる）で好きな色（`#rrggbb`。`squadColorOf`）を選びます（`squadColor`、ブラウザの好みなのでほかの PC にも付いていく）。選んだ色は Go の `SquadSetColor` で報告（`Report.Color`）に入れて送ります。
  - 色は全員が同じ規則で決めます（`assignColors`）。メンバー鍵の順に（つなぎ直しても変わらない。鍵のない古い版は中継の ID）、選んだ色をまだ誰も取っていなければその色、次に選んでいない人（と取れなかった人）が、名前から決まる色（`memberColor`）が空いていればその色、空いていなければ空いている最初の色です。同時に同じ色を選んでも、鍵の小さい人がその色になり、どの画面でも同じ結果になります。
  - ほかの人の色は選べません（押せず、誰が使っているかを出す）。選んだ色が取れなかったときは「今は自動の色」と出します。見るだけの PC（Client）は Host の色を選ぶので、使用中の印を付けません。
  - 色を選ぶ前のアプリ（報告に色がない）は、名前から色を決めるので、そのアプリの画面でだけ色が違うことがあります。
- **Host と Client**: 分隊の参加・退出と分隊カラーを両方向に揃えます（`squad:sync`。[settings-and-integrations.md](settings-and-integrations.md#host--client-モード)）。Host は Client から届いた変更をほかの Client にも伝えます。つながったとき Host がどの分隊にも入っておらず Client が入っていれば、Host が Client の分隊に入ります。Client は見るだけの PC（Host と同じプレイヤー）として参加し（`Report.Viewer`）、ほかの人の一覧と地図にはプレイヤーとして出ません。

### 自分のペン

マップに自分だけの線を描く道具です（`map-draw.js`、Go は `app_mapdraw.go`）。分隊の仲間には見えません（分隊で描くペンは [分隊の共有（計画）](squad-sharing.md)）。

- **始め方**: アイコンの列の鉛筆のボタンを押すと、地図の上の中央に道具の列が出ます。もう一度押すか、列の × か Esc で終わります。
- **道具**: ペン、消しゴム（触れた線を 1 本まるごと消す）、色 6 つ（スナップノートと同じ）、太さ 3 つ（描いたときの拡大率で画面上 3・5・9 px。線は描いたときの拡大率 `z` を持ち、見ている拡大率に合わせて地図と一緒に太く・細くなる。1 px から元の 8 倍まで。拡大して書いた字が、縮小して見ても潰れない。`z` の無い前の線は太さ一定）、元に戻す・やり直す（Ctrl+Z・Ctrl+Y / Ctrl+Shift+Z。このセッションのあいだだけ）、自分の線を隠す・表示（この画面だけ。保存しない）、この階の自分の線をすべて消す（元に戻せる）。
- **操作**: ペンを持っているあいだは、左ドラッグで描き、右ドラッグ・中ドラッグ・スペースを押しながらのドラッグで地図を動かし、ホイールで拡大縮小します。地点の印はポインタを通すので、印の上からも描けます（押しても開きません）。Leaflet のドラッグ・範囲ズーム・ダブルクリックのズームは止めます。右・中ドラッグは Leaflet のドラッグと同じく、動かしている間は地図の面をずらすだけ（1 フレームに 1 回、`move`）にして、離したときに 1 回だけ落ち着かせます（`moveend`。タイルや印の読み直し）。ウインドウ全体で追い、どちらのボタンも押されていなければ止めます（離したのを取りこぼしても動き続けない）。スペースは、ウインドウがキーボードを離れたら離したことにします（押したまま切り替えると、動かすモードのまま残るため）。中ボタンのブラウザの自動スクロールは止めます。
- **線**: ゲーム座標（1 cm 単位）で、描いたマップと階ごとに持ちます。表示中の階の線は濃く、別の階の線は地点と同じく設定 `fade` の濃さで薄く出します。消しゴム・元に戻す・すべて消すが効くのは表示中の階の線だけです。線は地点の印と分隊の印の上、ポップアップの下（`mapDraw` の pane、z-index 640）に、薄い影を付けて描きます。pane はポインタを通すので、ペンを置いているときは線の下の印も押せます。
- **保存**: 線 1 本が 1 件の記録で、`map-drawings.json`（`Records`、[user-data.md](user-data.md)）に保存します。変わってから 0.4 秒後に全部を `MapDrawingSave` に渡し、なくなった線は tombstone になります。起動後に初めて読み込む（`MapDrawingLoad`）までは保存しません（読む前の保存で、まだ読んでいない線を消さないため）。読めなかったときは 5 秒後にまた読みます。Host と Client はそれぞれの PC に保存します。

### 分隊ペン

分隊の全員が同じ地図に描けるペンです（`map-draw.js`、線の送受信は `squad-draw.js`、Go は `SquadSend` と `squad:message`、[分隊ルーム](settings-and-integrations.md#分隊ルーム)）。

- **始め方**: アイコンの列の、自分のペンの下にある鉛筆（右下に自分の分隊カラーの点。分隊の列の中）です。分隊に入っていないとき、つながっていないとき、中継が古いとき（`State.Drawing` が false）は押せず、理由をツールチップに出します。道具の列と操作は自分のペンと同じで、色の代わりに同じ印と表示名を出し、線を隠すボタンの代わりに「全員分消す」があります。道具の列の枠は自分の分隊カラーで、今どちらのペンで描いているかが一目で分かるようにしています。道具の列は中身の幅で、地図が狭いときだけ横にスクロールします（「全員分消す」を折り返さない）。
- **線**: 描いた人の分隊カラーで描き、`{id, by: メンバー鍵, name, c, map, floor, w, z, p, gen}` を持ちます。自分のペンの線と同じく、ゲーム座標でマップと階ごとで、別の階の線は薄く出ます。分隊ペンを持っているとき、分隊の線にポインタを乗せると、描いた人の名前を出します（自分のペンを持っているときと、分隊ペンで自分が描いた線には出さない）。
- **描いている途中**: 描き始め（`b`）と、0.05 秒ごとに増えた点（`p`、多すぎれば捨てる）を送り、ほかの人の地図では描いているそばから伸びます。離すと線全体（`l`）を送り、それが正式な線になります。5 秒続きが来ない途中の線は消します。
- **ペンの位置**: 分隊ペンを持っているあいだ、地図の上のポインタの位置を 0.05 秒ごとに送り（`c`。共同編集ツールのカーソルと同じくらい）、ほかの人の地図にその人の色の鉛筆と名前で出します。印は作り直さずに動かし、0.05 秒かけて次の位置へ滑らせます（拡大縮小のアニメーション中は滑らせない）。ペンを置く・地図の外に出ると消し、4 秒動かなければ消します。
- **自動で置く**: 分隊ペンは、3 分描かず地図の上でも動かさなければ自動で置きます。ペンの位置を送り続けないようにして、中継の部屋を眠らせるためです（中継の料金は部屋が起きている時間でほぼ決まる）。
- **消せるのは自分の線だけ**: 消しゴム・元に戻す・この階の自分の線をすべて消す は自分の線にだけ効きます（`e`。届いた消去も、送った人の線だけ消す）。人の線を自分の画面でだけ隠すこともしません（見ているものが人によって違うと話がかみ合わないため）。
- **全員分消す**: このマップの分隊の線を全員分消します。消去は 1 回ごとに ID の付いた出来事（`clears`: マップごとに `{id, gen, undone, at}`）で、新しい消去はそれまでのどれよりも大きい `gen` を持ちます（`x`）。マップの世代は取り消されていない消去の `gen` のいちばん大きいもので、それより古い世代の線は出しません。全員に「○○ がこのマップの分隊の線を消しました」と出て、8 秒のあいだは誰でも「元に戻す」で戻せます（`u`: その消去に `undone` を付ける）。取り消すと、全員が自分のその地図の線を送り直して保存し直します（取り消しの前に入った人・保存から読んだ人にも線がそろうように）。過ぎると消えた線は捨てます。消去は ID でまとめ、`undone` はどこか 1 つにあれば勝つので、誰が何をいつ聞いても保存しても、同じ線が出ます。
- **分隊の保存（中継）**: 中継の分隊の部屋に、メンバーごとの枠があります（`SquadStore` / `SquadStored`、[分隊ルーム](settings-and-integrations.md#分隊ルーム)）。そこへ自分の線と知っている消去（`{clears, lines}`）を、変えてから 10 秒後に（その間の変更はまとめて。描き続けても先へ延ばさない）、消しゴム・元に戻すでの消去と全員分消す・その取り消しは 1 秒後に置きます（消した線が保存から戻ってこないように）。つながると、まず全員の枠を読み、全員の消去を合わせてから線を取り込みます。なので全員が抜けたあとに来た人にも、1 人だけでも線が出ます。自分の線は、この PC に無いときだけ枠から取ります。
- **後から入った人**: 保存の最後の数秒の分は、いる人が渡します。新しい人の報告が届くと、それぞれが自分の線を、中継の ID がいちばん小さい人は抜けた人の線もあわせて送ります（`l`、消去付き）。取り消せるあいだの消去で隠れた線も送ります。自分の線を人から受け取ることはしません（持ち主は自分だけ）。
- **落ちて戻ったとき・再起動**: 自分の線は分隊ごとに 24 時間この PC にも残します（`SquadLinesSave`、`squad-lines.json`。中継に届かないとき用）。つなぎ直すと、中継の保存を読み終えてから（5 秒で読めなければそこで）、全員分消された線を捨て（取り消せるあいだの消去で隠れたものは残す）、残った自分の線を送り直します。ほかの人の画面では、メンバー鍵が同じなので同じ人の線のままです。
- **大きなメッセージ**: 1 件（封じる前で約 2800 文字）に入らない線は、分けて（`part`）送り、受けた側でつなぎます。一度に持つ分隊の線は 3000 本までです。
- **Client**: 見るだけの PC も分隊の部屋に入っているので、同じように描けます（自分のメンバー鍵で）。

### 分隊への共有

分隊ペンと同じ道（分隊の部屋のシェルのメッセージ、`squad-draw.js` の `sendShell`）で、分隊の仲間に物を渡します（`squad-share.js`）。分隊ペンが使えるときだけ出します。

- **ページ**: Web ページのツールバーの分隊のボタン（`squadShare`）か、サイドバーのタブの行のピンの左の分隊のボタン（ポインタを乗せると出る）で、そのタブのアドレスとタイトルを送ります（`share`）。押すと 2 秒だけチェックの印になります。あとから入った人にも、送った人が最近のもの（20 件まで）を送り直します。
- **スナップノート**: ノートの共有のメニューの「分隊に共有」で、書き込みごとの絵を長い辺 1600 px までの JPEG にして送ります（`snap`。大きければ 70% に縮めてもう一度）。1 件に入らないので分けて送り（`part`、1 件あたり約 2600 文字、10 秒 100 件まで）、ノートの上に「分隊に送っています… n%」と出します。大きいので、送ったときにいた人にだけ届きます。
- **スクリーンショット**: 2 つの道があります（`shot`。Host だけ。撮るのは Host なので）。
  - **位置に付ける**: マップの設定（歯車）の「位置にスクショを付ける」（`mapSettings.shotBubble`、最初はオフ。分隊ページにも同じスイッチ）をオンにすると、位置のスクショを長い辺 640 px の JPEG（`SquadShot(name, 'small')`、品質 70。30〜60 KB）にして、マップの自分の矢印の上に吹き出しで出します（一人でも）。位置のスクショは、ファイル名に位置があり（レイド中はどの画面でも入る）、解析でタスク・アイテム・キャラクターの画面と分からなかったもの（`kind` が `position`。解析を最大 10 秒待つ）です（`positionShot`。新しいスクショの `browser:screenshot` を `mayak:screenshot` で受ける）。分隊にいれば、同じ画像を位置（`x`・`z`）と一緒に送ります。送るのは 20 秒に 1 枚までで、待っているあいだに撮ったものは、いちばん新しい 1 枚に置き換えます（`queueSend`）。
  - **吹き出し**: 矢印が撮った場所（2 m 以内）にあるあいだだけ、その人の分隊カラーの枠の吹き出しで出ます（`view-map.js` の `drawBubbles`。仲間のものは受けたとき、自分のものは設定がオンのとき）。押すとマップの上に大きく出し（`openShot`、`.map-shot-box`）、枠の外・× ・Esc で閉じます。自分のものは撮ったままの大きさを読み、仲間のものは「大きい画像を見る」で頼めます（届くとその場で入れ替わる：`mayak:shot-large`）。
  - **手で**: スクショのビューアーの「分隊に共有」で、大きい画像を送ります。ボタンに「分隊に送っています… n%」と出ます。
  - **大きい画像のサイズ**: 分隊ページの「大きい画像のサイズ」（`squadShotSize`）で、元のまま・1080p（1920×1080 に収める。最初はこれ）・720p（1280×720）から選びます（品質 80）。手で共有したものと、頼まれたものに使います。
  - **二度送らない**: スクショはファイルの MD5（`SquadShotHash`）で見分けます。送ったものは分隊と MD5 ごとに覚え（`localStorage` の `mayak-squad-shots`、最新 500 件。再起動しても残る）、小さい画像は一度だけ、大きい画像は一度送ったら手では送りません（「このスクショはもう送っています」）。受ける側も、同じ人の同じ MD5 は 1 件にします（大きい画像が来たら小さい画像と入れ替える）。
  - **大きい画像を頼む**: 受けた小さい画像をビューアーで開くと「大きい画像を見る」があり、送った人に頼みます（`shotAsk`。頼んでいるあいだは「頼んでいます…」、20 秒まで）。送った人の MAYAK は、覚えているファイルから大きい画像を作って送ります（中継は一人だけに送れないので全員に届き、全員の小さい画像が入れ替わる。同じものは 1 分に 1 回まで）。送った人がつながっていないときや、ファイルが消えているときは届きません。
  - **受けたもの**: 分隊の欄の送った人の下に「(マップ) のスクショ」が 1 行、共有されたものの一覧に「スクショ」の種類で並びます。押すと分隊ページの上にビューアー（`.shot-viewer`）で開き、「スナップノートにする」で自分のノートにできます（Esc か × で閉じる）。1 人につき最新 30 枚だけ持ち、ページやノートとは別に数えます（スクショで押し出されない）。スナップノートと同じく、送ったときにいた人にだけ届きます。
- **ピン（ここを見てほしい）**: 分隊の列（下記）のピンのボタン（`mapPin`。分隊ペンが使えるとき）を押すと、ペンを置いて「ピンを刺す」状態になります（ポインタは指。もう一度押すか Esc でやめる）。そのあいだは地図を押すたびにそこへピンを刺し、2 回目からは同じピンを刺し直します（同じ id で動かす）。右ドラッグ・中ドラッグは、ペンと同じく地図を動かし、ピンは刺しません（左ドラッグもこれまでどおり地図を動かす）。送るのはマップ・階・位置と、刺したときの拡大率です（`pin`）。ピンは全員の地図に、刺した人の分隊カラーのピン（白の縁と中の点、足元に影）と、頭の横の名前で出ます（別の階なら薄く。刺した人の地図にも）。刺したとき・刺し直したときは上から落ちて、刺さってつぶれ、足元に波紋が出ます（受けた側でも。動きを減らす設定なら動かさない）。1 人 1 本で、新しく刺すと前のピンは消えます。モードを抜けたあとも、自分のピンはドラッグで動かせ（ペンを持っているあいだは不可。動かしたピンは落ち直さない：`drag`）、名前の横の × で抜けます（`unpin`）。10 分たつと消えます（動かすと延びる）。受け取っても地図は動かさず、分隊の欄の送った人の下と「共有されたもの」に「(マップ) にピン」が 1 行並び（動いても 1 行のまま、場所が変わる）、押すとそのマップと階に切り替え、刺した人の拡大率でその場所を真ん中にし、送った人の色の輪を 3 秒出します。あとから入った人には、刺した人が残り時間ごと送り直します（`age`）。前の版の「見ている範囲の共有」（`view`）は、その中心のピンとして受けます。
- **描いた**: 分隊ペンで誰かが線を引くと、「(マップ) に描きました」が 1 人・1 マップにつき 1 行、上に来ます（`l` の `new`）。
- **お知らせ**: 人から来たページとスナップノートとピンは、サイドバーの分隊セクションの、送った人の名前の右に未読の数で、いちばん新しいものは名前の下の段に出ます（[分隊](#分隊)。開いたものは既読）。分隊ページを見ても既読になります。分隊のボタンにも未読の合計を出します（畳んだサイドバーと横のタブ欄でも見える）。
- **マップの印**: 分隊の仲間が線を引くと、マップを見ていなければ、サイドバーの「マップ」の右に点が付きます（`mapFresh`）。マップを開くと消えます。
- **一覧**: 分隊ページの「共有されたもの」に全部（50 件まで、スクショは 1 人 30 枚まで別に。種類（すべて・ページ・スナップノート・スクショ・ピン・分隊ペン）と、共有した人（全員・一人ひとり。自分の分は「あなた」。共有した人が 2 人以上のときだけ出す）で絞れる）を、種類のアイコン、タイトル、送った人（色の点と名前）で並べます。人から来たページとスナップノートは、分隊ページを開くか押すまで太字と点で「未読」です。
- **開く**: ページは、同じページのタブ（`state.js` の `samePage`: 翻訳しているかどうか、`#` 以降、末尾の `/` は見ない）があればそれを前に出し、無ければ新しいタブで開きます（`openOrFocus`）。ブックマークを開くときも同じです。スナップノートは初めて開くときに自分のノートとして作り（`snapNew`）、次からはそのノートを開きます（消していれば作り直す）。「描きました」はマップを前に出して、そのマップにします（`mayak:map-show`）。「ここを見てほしい」は、そのマップ・階・中心・拡大率にします。
- **持つ期間**: この PC の、その分隊にいるあいだだけです（保存しない。分隊を抜けたり変えたりすると消える）。

## ツールバーのアイコンの並び

Web ページのツールバー右側のアイコン（翻訳、スナップノート、分隊に共有、Wiki 検索、外部ブラウザで開く。分隊に共有 は分隊ペンが使えるときだけ）は 1 つのグループで、ドラッグで並べ替えられます（`tool-drag.js`）。既定の並びはこの順で、スナップノートは Wiki 検索の左です。押したまま 5px 動かすとドラッグになり、離すと並びを `toolOrder` として `browser.json` に保存します（再起動しても戻る）。そのページに出ていないアイコン（タスク以外での Wiki 検索など）は、並びの中の位置を保ちます（`mergeToolOrder`）。ドラッグ中はシェルの再描画を止めます。

## ページの上のメニュー

ページはシェルより上に重なるネイティブビューなので、シェルが描くメニューはページの下に隠れます。スナップノートのメニューは、メインウインドウをオーナーにした枠なしの小さなウインドウ（`menu.html`、`app_menu.go`）で開きます。シェルが項目を送ると（`BrowserMenuShow`）、項目数から見積もった高さですぐに表示し、メニューのページが描き終えた高さ（`BrowserMenuReady`）に合わせます。ウインドウを作った直後の最初のメニューは、ページの読み込みより先に送られて届かないので、メニューのページは読み込み時に今のメニューを取りに行きます（`BrowserMenuCurrent`）。選んだ項目は `menu:choice` イベントでシェルに戻ります。ほかをクリックしてフォーカスが外れるか Esc で、選ばずに閉じます。上下の矢印キーで項目を移れます。

## ボス

各マップのボスの出現率と、Goons の目撃報告を見られます。データは `json.tarkov.dev/{regular|pve}/maps`（名前は `maps_{言語}`）から Go 側（`internal/bossinfo`、`BrowserBosses`）が取得します。ゲームモードはアイテム欄と同じ決め方（検出中のモード。seasonal は regular）です。

- **取得:** マップのデータは圧縮後も約 0.8MB あるため、4分以内は前回の結果を使い、それ以降は ETag 付きで問い合わせて、変わっていなければ前回のデータのままにします。シェルは起動時と5分ごと（ウインドウが見えている間）、表示言語を変えたとき、ボスのページを開いたときに取り直します。
- **表示するボス:** `boss` で始まるもの、カルトの司祭、レイダー。AI の PMC などは出しません。同じボスが1つのマップに複数の出現枠を持つときは1行にまとめ、出現率は高い方、出現場所は全部をまとめます。
- **Goons:** `goonReports`（プレイヤーの報告。マップと時刻）を新しい順に最大20件持ちます。新しさで色を変えます（1時間以内は緑、3時間以内は黄、それより前は赤）。経過時間は再描画なしで30秒ごとに更新します。
- **サイドバー:** スクリーンショットの下に「ボス」の欄があり、最新の Goons の報告と、マップとモードのドロップダウン、そのマップのボス上位5件と出現率を出します。マップ・モードとも既定は「自動」（検出中のマップ＝Host の `currentMap`、プレイ中のモード）で、手で選ぶこともできます（`bossMap` / `bossMode`、ボスのページと共通）。見出しで開閉し、Goons の下の「マップのボス」の行でマップのボスを出し入れします（`bossesView` = `full` / `goons` / `closed`）。Goons は Knight の出現枠（Big Pipe と Birdeye が取り巻き）なので「Goons」と表示します。見出し横のアイコン（折りたたんだサイドバーと横レイアウトではアイコンだけ）でボスのページを開きます。
- **ボスのページ:** Goons の報告（最大10件、時刻つき）と Goons が出るマップの一覧、マップを選んでボスごとの出現率・出現場所ごとの確率・取り巻きを表示します。見出しに同じマップ・モードのドロップダウンがあり、検出中のマップには ● 印が付きます。時刻は設定の「時刻の表示」（24時間 / 12時間）に従います。
- **Goons の報告:** ボスのページの「Goons を報告」、またはサイドバーのボス欄の見出し横の旗アイコン（ボスのページを開いてダイアログを出します。折りたたんだサイドバーと横レイアウトにはありません）から、Goons を見たことを tarkov.dev の公開の受付口（`manager.tarkov.dev/api/goons`）に送れます（`BrowserGoonReportInfo` / `BrowserReportGoons`、`bossinfo.SendReport`）。
  - 報告するアカウントとモードは、EFT のログで見つかったもの（`trackerData.Profiles`）から選びます。アカウントとモード（PvP / PvE）ごとに1つにまとめ、プレイ中のもの、最近見たものの順に並べます。シーズンモードは受け付け先にないので出しません。ログにないアカウントでは送れません。
  - 時刻は、今のレイドか直前のレイド（終了時に覚え、再起動後はログの最後のレイド開始と最後に検出したマップ）の開始時刻、または今の時刻です。24時間より前のレイドは送れず、同じレイドは1回だけです（アプリの起動中）。
  - マップは Goons が出るマップだけで、ゲーム内の名前（`nameId`、例 `bigmap`）で送ります。送信前に、IP アドレスとアカウント ID が tarkov.dev に記録されることを表示します。tarkov.dev はアカウント ID が送信者本人のものかを確かめません（記録として保存するだけ）。
  - 報告は tarkov.dev のデータに10分ごとにまとめられるため、11分後に取り直します。

## ツールバーとアドレス欄

- 通常の `web` / `blank` タブ: 戻る・進む・再読み込み・アドレス欄。`web` タブでは右端に「既定のブラウザで開く」ボタンが付きます（`Browser.OpenURL`、http/https のみ）。
- アドレス欄は Chrome と同じく URL と検索の両方を受け付けます（`state.js` の `resolveAddress`）。`http://` / `https://` で始まるもの、ドットを含むホスト名、`host:port`、IPv4、`localhost` は URL として開き（スキームがなければ `https://` を補います）、それ以外（空白を含むもの、単語だけ、`3.14` のようなもの）は Google 検索（`https://www.google.com/search?q=`）にします。先頭に `?` を付けると必ず検索です。`file:` や `javascript:`、認証情報付きの URL は開かず検索になります。`web` / `blank` タブでは現在のタブを移動させ、それ以外のタブからは新しいタブを開きます。Enter で移動したあとはページにキーボードフォーカスが移り、Esc はタブの URL に戻してページへ戻ります。
- キーボードショートカットは Chrome に合わせています（`state.js` の `shortcut()`。macOS では Ctrl の代わりに Cmd も使えます）。Ctrl+T 新しいタブ（アドレス欄にフォーカス）、Ctrl+W / Ctrl+F4 タブを閉じる（ピン留めは除く）、Ctrl+Shift+T 最後に閉じた Web タブを元の位置に開き直す（起動中に閉じた 20 件まで、保存はしない）、Ctrl+Tab / Ctrl+PageDown 次のタブ、Ctrl+Shift+Tab / Ctrl+PageUp 前のタブ、Ctrl+1〜8 タブの並び（`state.tabs`。マップや設定などシェルのページも含む）で n 番目のタブ、Ctrl+9 最後のタブ、Ctrl+L / Alt+D / F6 アドレス欄にフォーカス、Ctrl+D 表示中のページをブックマークしてサイドバーにピン留め。
  - ページビュー（WebView2 の子ウインドウ）にフォーカスがあるときは、シェルの `keydown` には届きません。Windows では各ビューの `AcceleratorKeyPressed`（`view_windows.go` の `acceleratorKey`）が修飾キー付きのキーをキー名（`event.key` を小文字にしたもの）に直して `SetKeyHandler` に渡し、Go 側の許可リスト（`app_browser.go` の `browserShortcutKey`。`shortcut()` と同じ組み合わせ）にあるものだけ `browser:key` イベントでシェルに送り、ページには渡しません。それ以外のキー（Ctrl+R、Ctrl+F、Ctrl+C など）はページのままです。macOS / Linux ではページ内のキーは転送しません。
  - タブを切り替えたあとのキーボードフォーカスは、Web タブならそのページ、シェルのページ（設定など）ならシェルに移します（`BrowserView` の `focus` コマンド。ID `shell` はウインドウの `Focus()`、それ以外はビューの `MoveFocus`）。ページビューはネイティブのウインドウなので、シェルからは `focus()` だけでは移せません。
- **翻訳ボタン**（`translate-page`、Web タブだけ）: Fandom の Wiki（公式 Wiki を含む `*.fandom.com` と、その翻訳ページ）では、右側の欄（`.page__right-rail`。サインアウト中は「Fandom は初めてですか？」の欄と広告）を `sites.js` で隠します。翻訳しているかどうか、サインインしているかどうかによらず、Windows と Mac で同じです。Chrome の「ページを翻訳」は WebView2 に無いので、代わりに Google 翻訳のプロキシで開き直します（`state.js` の `translatedURL`）。ホスト名のドットをハイフンに（元のハイフンは `--` に）して `.translate.goog` を付け、`_x_tr_sl=auto`・`_x_tr_tl`・`_x_tr_hl`（表示言語: ja / en）を付けます。翻訳中はボタンが点灯し、もう一度押すと元の URL に戻します（`originalURL`。`_x_tr_*` を外してホスト名を戻す）。プロキシは別オリジンなので、ログインが要るページや tarkov.dev の Remote Control には向きません。タスクのサイト選択は翻訳前の URL で判定します（`sitesForURL`）。
- 設定 → タスク の「公式 Wiki（英語）を翻訳して開く」（`translateWiki`、`browser.json`）をオンにすると、タスク検出で開く公式 Wiki のページを最初から翻訳版で開きます（`receiveTask`）。日本語 Wiki と tarkov.dev には掛かりません。
- Google が翻訳プロキシの前にロボットの確認（`google.com/sorry`、`continue=` に翻訳ページ）を出すことがあります。確認を通すと Google は翻訳ページに `google_abuse=…`（Cookie の形の値）を付けて戻しますが、プロキシはこの付いた URL を自分自身へリダイレクトし続け、WebView は「リダイレクトが多すぎます」で止まります（ブロックされていなくても起きる、Google 側の動き）。タブがこのページに移ったら（`translateCheck` の `passed`）、`google_abuse` を外した翻訳ページを開き直します。開き直してから 2 分以内に同じページでまた確認が出たら（`check`）、翻訳を諦めて元のページを開き、エラーバーに理由を出し、その後 1 時間はタスク検出でも公式 Wiki を翻訳せずに開きます（`translatePausedUntil`、保存しない）。翻訳ボタンはその間も使えます。
- 戻る・進むのボタンは、ナビゲーションイベントの `canBack` / `canForward` に合わせて有効・無効が切り替わります。
- 再読み込みは Ctrl+Shift+R と同じくキャッシュを無視します。DevTools プロトコルの `Page.reload`（`ignoreCache: true`）を使い、失敗した場合だけ通常の再読み込みになります（`browser_tabs.go` の `BrowserCommand`）。キャッシュが壊れたときも再読み込みで回復させるためです。

### ロードバー

- WebView2 の `NavigationStarting` で読み込み中、`NavigationCompleted` で完了とみなし、`browser:navigation` イベントの `loading` として送ります。
- シェルは読み込み中のビュー ID を `loadingViews` で覚えておき（保存はしません）、アクティブなタブが読み込み中なら、アドレス欄の下端に 2px のバーを左右に往復させます（`loadBar()`、1.4 秒周期）。
- アニメーションの位相は時刻から決まる（`--load-offset`）ため、再描画してもアニメーションは最初からやり直しになりません。`prefers-reduced-motion` のときは静止したバーを表示します。

## ファビコン

- ページが報告したファビコン URL（WebView2 の `FaviconChanged`、または他の変更と一緒に読む `faviconURI()`）をタブに記録し、ホスト名ごとに `favicons` に覚えます（最大 200 ホスト）。ブックマークのアイコンにも使われます。
- 別のホストへ移動すると、新しいアイコンがわかるまで古いアイコンを外します。
- 画像は Go 側のキャッシュ（`app_favicon.go`）から data URL として受け取ります。
  - 保存先は `Mayak/favicons`。ファイル名は URL の SHA-256 の先頭 16 バイトで、`.img` と `.type` の 2 ファイルです。
  - ページが同じアイコンを再報告したとき（`refresh`）は、キャッシュが 10 分（`faviconRefresh`）より古ければ取り直します。取得に失敗した場合はキャッシュを返します。
  - 取得のタイムアウトは 10 秒、最大 256 KiB。`image/*` でなければ拒否します（`.ico` は判定を補っています）。
  - `localhost`、`*.localhost`、`*.local`、ループバック・プライベート・リンクローカル・未指定 IP は取得しません（`faviconURLAllowed`）。取得はアプリ自身が行うため、ページにローカルマシンや LAN を指させないためです。
- 起動時に既知のアイコンをすべて読み込むので、オフラインでもすぐ表示されます。`<img>` は `referrerpolicy="no-referrer"` で読み込みます。アイコンを知らないサイトのブックマークは頭文字で表示します。
- **ブックマークのアイコンの先読み**: タブで開いたことのないサイトのブックマークは、Go がページを読んでアイコンを探し、キャッシュしておきます（`BrowserSiteIcon`）。ページの head の `<link rel="icon">`（`shortcut icon` も。文書の順）、次に `apple-touch-icon`、なければ `/favicon.ico` の順に、読み込めた最初のものを使い、`favicons` にそのブックマークのホストで覚えます。ページは 512 KiB まで、リダイレクトは 5 回まで・行き先ごとに `faviconURLAllowed` で確かめます。起動時と、ピン留めしたとき・ブックマークを足したり直したりしたときはそのブックマークを、ブックマークのページを開いたときは全部を（ピン留めのものが先）、1 件ずつ順に裏で調べます。1 つのサイトは 1 回の起動で 1 度だけ試します。ブラウザ以外の読み込みを断るサイト（Fandom など）は見つからず、タブで開いたときに付きます。読み込めない場合、タブとサイドバーでは地球アイコンに置き換え、ブックマークページでは画像を取り除きます。

## 広告ブロック

`app_adblock.go` と `internal/adblock`（AdGuard の urlfilter エンジン）で実装されています。Windows と Mac で有効です（Linux はまだ）。

- フィルタリスト: EasyList、EasyPrivacy、AdGuard 日本語フィルタ（`DefaultLists`）。`Mayak/adblock/<name>.txt` にキャッシュします。
- 更新: 4 日（`maxAge`）より古いリストをダウンロードし、6 時間（`retryAfter`）ごとに確認します。1 リストは最大 32 MiB です。
- `tarkov.dev` とそのサブドメインは、広告で運営されているため対象外です（`Exempt`）。
- ページ本体（トップレベルのドキュメント）はブロックしません。サブリソース（画像、スクリプト、XHR/fetch、iframe など）を WebView2 の `WebResourceRequested` で判定してブロックします（`internal/browserview/filter_windows.go`）。
- ブロックした画像・iframe・メディアの跡は `collapse.js` で詰め、要素非表示ルールは `DOMContentLoaded` で CSS として挿入します。ホスト名の親ドメインのルールも適用します。
- 設定の ON/OFF はすぐに反映され（`BrowserSetAdblock`）、表示中の `web` タブを再読み込みします。
- **Mac**: WKWebView は通信を 1 件ずつ確かめられないので、リストを WebKit のコンテンツブロッカー（WKContentRuleList）に変換して、全タブ（とタブが開いたポップアップ）に付けます（`webkit.go` の `WebKitRules`、`view_darwin.go` の `watchRules`）。
  - 変換するのは、WebKit の正規表現で言えるネットワークのルール（`||`、`|`、`*`、`^`。種類、third-party、`domain=`）と、WebKit が確実に受け付けるセレクタの要素非表示（`:has` などの拡張、疑似要素、多くの疑似クラスは除く）、例外（`@@`）です。正規表現のルールや `redirect`・`removeparam` などは外します。今のリストで約 11.6 万件（上限 15 万件に対し 14 万件まで。多いときは要素非表示から削る）。
  - 並びはブロック → 要素非表示 → 例外（`ignore-previous-rules`）→ `tarkov.dev` の除外です。ページ本体と popup は対象外です。
  - WebKit はリストの版（内容のハッシュ）ごとにコンパイルしたものを保存し、同じ版なら次の起動ではすぐ使います。古い版は消します。要素非表示を WebKit が受け付けなかったときは、ネットワークのルールだけでコンパイルし直します。
  - アプリが Blocker を渡した時点（`SetContentBlocker` → `blockerSet`）で始め、リストが更新されたとき・ON/OFF を変えたときは、Blocker の `OnChange` で付け直します。
  - うまく効かないときは、MAYAK のログの「Ad blocking ready」（リストの読み込み）と、macOS のコンソールの「MAYAK: content blocker」（WebKit がコンパイルを断ったとき）を見ます。
  - 要素非表示は Windows と同じく `DOMContentLoaded` でも CSS（`--rl` の印つき）として挿入し、`collapse.js` が隠した広告のまわりの空いた枠を詰めます。タブは `collapse.js` を `WKUserScript` で読み込み、`DOMContentLoaded` で `mayakAdblock` のメッセージを送ると、Go（`mayakBrowserCosmetic`）がそのページの CSS を返します。ブロックした画像・iframe の通知は WebKit から来ないので、それだけで詰めることはしません。

## ネイティブビュー

### 配置

`api.js` の `bounds()` がウインドウ内のページ領域を論理ピクセルのインセットで決め、`BrowserView('show', …)` で送ります（`browserview.Options`）。

| 項目 | 値 |
| --- | --- |
| `Left` | 左に置いたタブ欄の幅（閉じているときは 52）＋左に置いたアイテム欄の幅 |
| `Top` | 縦レイアウトは 48、横レイアウトは 96 |
| `Right` | 右に置いたタブ欄の幅＋右に置いたアイテム欄の幅 |
| `Bottom` | 下に置いたアイテム欄の高さ。それ以外は 0 |

アイテム欄が閉じているときは、その分は 0 です。

Windows 実装（`internal/browserview/view_windows.go`）の動作:

- インセットはウインドウの DPI（`GetDpiForWindow`、既定 96）で物理ピクセルに換算します。
- 最大化していないときは、右端と下端に少なくともリサイズ枠（`SM_CXSIZEFRAME + 1`）の幅を空けます。フレームレスウインドウをシェルの端からリサイズできるようにするためです。
- 各タブは、クリップ付きの子 `STATIC` HWND に 1 つずつ WebView2 を埋め込みます。`WM_SIZE`・`WM_DPICHANGED` で再配置し、`WM_MOVE` では WebView2 に親ウインドウの移動を通知します。
- 切り替え時は新しいビューを先に表示してから他のビューを隠します（`showOnly`）。間にシェルが一瞬見えるちらつきを防ぐためです。ページが描画されるまでの背景は、テーマの `--bg` 色で塗ります。
- アクティブなタブが `web` 以外（設定・ブックマーク・新規タブ・タブなし）のときは `hideAll` ですべてのビューを隠します。
- 閲覧データは `Mayak/browser-webdata` に置きます。
- macOS（WKWebView）と Linux（WebKitGTK）の実装も `internal/browserview` にあります。

### シェルのオーバーレイを重ねられない理由

ページはシェルの WebView より手前にあるネイティブの子ウインドウです。そのため、シェルの HTML をページの上に重ねて描くことはできません。影響と対処は次のとおりです。

- ブックマークの右クリックメニューがサイドバーからはみ出す場合は、`overlay` アクションでビューを `hideAll` し、閉じたら元に戻します。
- アイテム欄は `Left` / `Right` / `Bottom` インセットでページ領域の外に置かれます。アイテム検索のポップアップもその中に収まります。
- アイテムサイドバーから開くページは、シェルの中ではなく別ウインドウ（次節）に表示します。
- ページ上で離したドラッグはシェルに届かないため、タブのドラッグはフォーカス喪失などで破棄します（前述）。

## アイテムポップアップウインドウ

アイテムサイドバーのタスク行や、見出しのアイテムのアイコン・名前をクリックすると、ページが専用のポップアップウインドウで開きます（`app_popup.go`、`frontend/popup.html`、`frontend/src/browser/popup.js`）。

- **ウインドウ**: フレームレスで、タスクバーには表示しません。最小サイズは 320×200。メインウインドウを owner に設定するため（`app_popup_windows.go` の `GWLP_HWNDPARENT`）、メインウインドウより常に手前にあり、メインウインドウの外へ動かしても同様で、メインウインドウと一緒に最小化されます。
- **中身**: 上部の 44px（`popupHead`）はヘッダーで、ここをドラッグすると移動できます。ページはその下のネイティブビュー（ID `popup`）です。左端 5px（`popupEdge`）と、右端・下端のリサイズ枠は空けてあり、そこからリサイズできます。
- **ヘッダー**: タスク / 地球のアイコン、タイトル（ページ内のリンク移動に追従）、ピン、「タブで開く」、「外部ブラウザで開く」、閉じる。読み込み中はヘッダー下端にロードバーを表示します。テーマと言語はシェルと同じです。Esc で閉じます。
- **初回の配置**（`popupPlace()`）: アイテムサイドバーのすぐ左（間隔 8px）に置き、縦位置はクリックした行の高さを基準にします（行の中心から 160px 上、上下の余白 12px の範囲内）。幅は 320〜960、高さは 240〜800 です。
- **位置の記憶**: 開いてから 500ms 以降の移動・リサイズは `popup.json` に保存されます（最小化中や 320×200 未満は除きます）。次回からはその位置とサイズで、再起動後も画面内に収めて開きます。すでに開いているポップアップは動かしません。
- **フォーカスを失ったとき**: ピン留めしていなければ閉じます。ただし 200ms 待ってから、その間に別のページが表示されていないか（`gen`）を確認します。このため、ポップアップを開いたまま別のタスク行をクリックすると、閉じずに中身が切り替わります。
- **同じ行を再度クリック**すると閉じます。フォーカス喪失で閉じた直後（500ms 以内）に同じ行をクリックしても、すぐ再表示はしません。開いてから 300ms 以内に届いた「閉じた」通知は無視します。
- **ピン**: ピン留め中は、ほかをクリックしても閉じません。閉じるとピンは解除されます。
- **閉じる**: ビューを破棄してウインドウを隠します。次のポップアップに前のページが残らないようにするためです。Alt+F4 やウインドウの閉じる操作も同じ扱いで、ウインドウ自体は再利用します。
- **タブで開く**: 現在のページ（タスク情報を含む）を新しいタブに移し、ポップアップを閉じます。
- ポップアップのビューにも、広告ブロックと tarkov.dev の Remote Control 用スクリプトが適用されます。開いている間、クリックしたタスク行や見出しのアイテム名には `popup-source` クラスが付き、アクセント色の枠で強調されます。

## 初回チュートリアル

Host で初めて起動したとき（`browser.json` の `tutorialDone` が `true` でないとき）、シェルは 7 ステップのチュートリアルをオーバーレイで表示します。ようこそ → EFT のフォルダ（`GetSettings` で見つけたスクリーンショット / ログのフォルダを表示）→ スクリーンショットキー → マップ → 別の PC や普段のブラウザ（tarkov.dev 連携）→ TarkovTracker → 完了、の順です。各ステップのボタンは、対応する設定セクション（`settings` → `settingsSection`）やマップ（`livemap`。マップの無いリリース版では何もしない）を開きます。

- 操作: 「次へ」「戻る」「スキップ」「あとで」「完了」のボタンのほか、Enter / → で進み、← で戻り、Esc で閉じます。
- 閉じるかスキップすると `preferences` で `tutorialDone: true` を保存します。設定 → 表示 の「チュートリアルを表示」でいつでも再表示できます。
- 表示中は `overlay` アクションでネイティブビューを隠します。`api.js` は `overlay` フラグを持ち、表示中にほかの理由で `show()` が呼ばれてもビューを出しません。閉じるとアクティブなタブのビューを戻します。
- オーバーレイには出現アニメーションを付けていません。Web タブが表示中のシェルではアニメーションが進まず、フェードインの最初の透明なフレームで止まって見えたためです（`style.css` の `.tutorial`）。

## 再描画の挙動

シェルは状態が変わるたびに `#app` の `innerHTML` を作り直します（`shell.js` の `render()`）。作り直しても使い勝手が変わらないように、次の処理をしています。

- フォーカス中の入力欄、入力途中の値、カーソル位置を復元します。
- `.item-body`、`.tab-strip`、`main`、`.item-results` のスクロール位置を保持します（`main` はタブが変わった場合のみ先頭に戻します）。
- 描画直後の 2 フレームは `.rendering` クラスで CSS トランジションを止めます。ポインタの下で作り直された要素が、毎回ホバー色へフェードするのを防ぐためです。
- タブのドラッグ中は描画を保留し、ドロップまたはキャンセル後に描画します。
- ロードバーは時刻に基づく位相で描画するため、再描画で途切れません。
- アイテムの「◯分前」表示は 30 秒ごとに、DOM を作り直さずに文字だけ更新します。

## セキュリティ上の制限

- **URL の検証**: シェル（`webURL()`）、Go（`BrowserView`）、WebView2（`browserURL()`）のすべてで、http/https のみ、ユーザー名・パスワードを含まない、`wails.localhost` ではないことを確認します。`NavigationStarting` でも検査するため、リダイレクト先も対象になります。
- **新しいウインドウ**: ページの `window.open` などは `NewWindowRequested` で受けます（`browser_tabs.go`）。ユーザー操作によらないものは開きません（ポップアップブロック）。ユーザー操作によるもののうち、`target=_blank` のリンクのようにサイズも位置も指定しないものは新しいタブとして開きます（ポップアップウインドウからの場合も新しいタブ）。サイズか位置を指定した `window.open`（`ICoreWebView2WindowFeatures` の `HasSize` / `HasPosition`）は、開いた側に結果を返すダイアログ（Google ログインの `accounts.google.com/gsi/transform` は `window.opener` に postMessage して自分で閉じる）なので、イベントを未処理のままにして WebView2 に本物のポップアップウインドウを作らせます。タブにすると `window.opener` がなく、そこで止まってしまうためです。このウインドウは同じプロファイル（Cookie）を使いますが、広告ブロックや Remote Control のスクリプトは付きません。
- **分離**（`BrowserIsolation`）: Web メッセージングは無効、ホストオブジェクトの登録なし、権限要求はすべて拒否します。外部ページには Wails のバインディングも `window.mayakDesktop` も渡りません（`window.mayakDesktop` は信頼できるシェル文書だけのものです）。
- **命令の検証**: `BrowserView` はビュー ID（`^[a-zA-Z0-9_-]{1,80}$`）、インセット（0〜4096）、命令名（`show` / `navigate` / `hideAll` / `close` / `back` / `forward` / `reload`）を検証します。`BrowserPopupShow` も配置の範囲を検証します。
- **保存データ**: `browser.json` にはトークンや接続コードを保存しません。ペアリングの鍵（`connection.link`）はこの PC のデータとして保存し、同期しません。ファビコンの取得先はローカル・LAN のアドレスを除外しています。
