# Wails v3 migration

MAYAK now uses Wails `v3.0.0-beta.24`, pinned together with the frontend
`@wailsio/runtime` package. Go 1.25 is the minimum; `go.mod` selects toolchain
1.26.8. The official guide is
https://v3.wails.io/migration/v2-to-v3/ .

## Application changes

- `internal/app/run.go` (started by the root `main.go`) creates an `application.App`, registers the existing App as a service,
  and creates the trusted main `WebviewWindow`.
- `ServiceStartup` and `ServiceShutdown` own the existing monitoring lifecycle.
- Window operations and file/directory dialogs use the v3 window/dialog APIs.
- Tray menus use Wails' built-in SystemTray manager. The separate systray
  dependency and 50ms minimise polling loop have been removed; a native minimise
  event now drives tray hiding.
- `frontend/bindings` is generated by the pinned v3 CLI. Runtime events unwrap
  `event.data` before reaching the existing UI handlers.
- The trusted settings iframe calls the main document's typed service bridge;
  it does not instantiate a second Wails runtime or event dispatcher.

## Native browser isolation

Wails v3 supplies the public `NativeWindow` and UI-thread dispatch APIs. The
previous fork of Wails v2 is no longer needed. Native browser adapters now live
in `internal/browserview`, outside the framework:

- Windows: separate WebView2 controllers, no host messaging or Wails scripts;
  native resize/DPI notifications resize tabs in the main window.
- macOS: plain WKWebViews attached to the public NSWindow content view.
- Linux: native overlays for Wails v3's default GTK4/WebKitGTK 6.0, with a GTK3 /
  WebKitGTK 4.1 path when compiled with `-tags gtk3`.

The small isolated-browser extension of `go-webview2` remains under
`third_party/go-webview2`; this is a native WebView wrapper, not Electron. The
official Wails v3 module is used without a local replacement/fork. External pages
never receive the service bridge. WebRTC remains in the trusted main document.

## Build

```powershell
go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0-beta.24
wails3 task build
```

No CLI installation is required for the equivalent pinned command:

```powershell
go run github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0-beta.24 task build
```

This generates bindings, installs the frozen bun lockfile, builds the frontend,
generates Windows resources, and compiles `build/bin/Mayak.exe`. It does not
launch the application. `wails3 dev` and `wails3 task run` do launch it.

`Taskfile.yml` and `build/config.yml` replace v2's `wails.json`. Windows resources
now contain concrete product metadata instead of v2 template placeholders.

## Data and verification

The migration does not write to live user settings. Existing configuration
paths, browser state, window geometry and protected TarkovTracker storage are
preserved. It does not overwrite the old running executable.

Verified on Windows without launching MAYAK: v3 binding generation,
TypeScript/Vite build, production executable build, compilation of Go packages,
offline browser/pairing validation and temporary-directory persistence tests.

Still pending the user's explicit test request: application startup, live tab
rendering/resizing, tray/close behaviour, file dialogs, WebRTC connection tests,
and macOS/Linux builds and runtime checks. No live monitoring, UI manipulation,
listeners or application restarts were performed for migration verification.
